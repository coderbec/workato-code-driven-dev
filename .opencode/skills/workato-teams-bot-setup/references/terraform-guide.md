# Terraform Deployment Guide

## Overview

The generated Terraform configuration automates Azure AD app registration and configuration for Workato Teams bots.

## File Structure

```
teams-bot-terraform/
├── main.tf              # App registration, service principal, client secret
├── variables.tf         # Input variables
├── outputs.tf           # Output values
├── terraform.tfvars     # Pre-populated variable values
└── README.md           # Generated by script
```

## Prerequisites

- Terraform CLI (v1.0+): `terraform --version`
- Azure CLI: `az --version`
- Logged into Azure: `az account show`
- Appropriate Azure AD permissions (Application Administrator or higher)

## Deployment Steps

### 1. Initialize Terraform

```bash
cd teams-bot-terraform
terraform init
```

This downloads the Azure provider and sets up the working directory.

### 2. Review Plan

```bash
terraform plan
```

Shows all resources that will be created:
- Azure AD App registration
- Service Principal
- Client Secret (with 1-year expiration)

### 3. Apply Configuration

```bash
terraform apply
```

Confirms and creates resources. When prompted, type `yes` to proceed.

**Output:** App ID, Object ID, and confirmation of secret creation.

### 4. Retrieve Client Secret

⚠️ **Client secrets cannot be retrieved from Terraform output for security.**

If you need to rotate or view the secret:

```bash
az ad app credential list \
  --id $(terraform output -raw app_id) \
  --query "[0].{displayName:displayName,endDate:endDate}"
```

To create a new secret (old one expires in 1 year):

```bash
az ad app credential reset \
  --id $(terraform output -raw app_id) \
  --display-name "WorkatoBotSecret" \
  --query password -o tsv
```

## Variables Reference

| Variable | Type | Required | Notes |
|----------|------|----------|-------|
| `bot_name` | string | Yes | App registration display name |
| `client_id` | string | Yes | Azure AD Client ID (from Workato) |
| `client_secret` | string | Yes | Azure AD Client Secret (marked sensitive) |
| `data_center` | string | Yes | Workato data center (us, eu, jp, etc.) |
| `oauth_redirect_uri` | string | Yes | Auto-determined from data_center |
| `azure_subscription_id` | string | No | If omitted, uses default subscription |
| `azure_resource_group` | string | No | Resource group for organization |

## Sensitive Variables

The following variables are marked `sensitive = true` to prevent accidental exposure:

- `client_id`
- `client_secret`

These values will **not** be displayed in Terraform output or logs. If you need to view them:

```bash
terraform state show 'azurerm_ad_application_password.teams_bot'
```

⚠️ **Caution:** Terraform state files contain sensitive data. Store them securely:
- Use remote state (Azure Storage, Terraform Cloud)
- Restrict file permissions: `chmod 600 terraform.tfstate`
- Consider encryption

## Post-Deployment Steps

After `terraform apply` succeeds:

1. **Note the App ID** output for Teams Developer Portal configuration

2. **Manual Azure Portal Setup:**
   - Go to https://portal.azure.com
   - Find your app in **App registrations**
   - Go to **Authentication**
   - Add Web platform with redirect URI (if not auto-configured)

3. **Configure in Workato:**
   - Go to **Platform > Workbot > Custom bots > Step 3**
   - Enter Client ID and Client Secret
   - Save the custom OAuth profile

4. **Configure in Teams Developer Portal:**
   - Create the bot and app
   - Reference Workato bot endpoint address
   - Set permissions and scopes

## Scaling Multiple Bots

To manage multiple Teams bots, use Terraform workspaces:

```bash
# Create workspace for each bot
terraform workspace new bot-hr-team
terraform workspace new bot-finance-team

# Switch between workspaces
terraform workspace select bot-hr-team

# Each workspace has its own state
terraform plan
terraform apply
```

Or use separate directories:

```
teams-bots/
├── hr-team-bot/
│   └── [terraform files]
├── finance-team-bot/
│   └── [terraform files]
```

## Troubleshooting

### Error: "The subscription does not have Workload Identity"
Solution: Ensure your Azure subscription has sufficient quota and permissions for app registrations.

### Error: "Permission denied" when creating app registration
Solution: Your user account needs **Application Administrator** or **Global Administrator** role:
```bash
az role assignment list --include-inherited --query "[].{Scope:scope,Role:roleDefinitionName}"
```

### Client secret not visible in output
By design, Terraform doesn't display sensitive values. Retrieve it via Azure CLI:
```bash
az ad app credential list --id <APP_ID>
```

### Need to rotate secret
```bash
# Create new secret
NEW_SECRET=$(az ad app credential reset --id <APP_ID> --display-name "WorkatoBotSecret" --query password -o tsv)

# Update Workato and Terraform
echo "New secret: $NEW_SECRET"
terraform destroy -target=azurerm_ad_application_password.teams_bot
terraform apply
```

## State Management

### Local State (Default)
Terraform stores state in `terraform.tfstate` (plaintext, **NOT production-ready**).

### Remote State (Recommended)
Use Azure Storage for remote state:

```hcl
terraform {
  backend "azurerm" {
    resource_group_name  = "rg-terraform-state"
    storage_account_name = "tfstate12345"
    container_name       = "teams-bots"
    key                  = "terraform.tfstate"
  }
}
```

Configure backend:

```bash
terraform init \
  -backend-config="storage_account_name=tfstate12345" \
  -backend-config="container_name=teams-bots" \
  -backend-config="key=terraform.tfstate" \
  -backend-config="resource_group_name=rg-terraform-state"
```

## Cleanup

To remove all resources created by Terraform:

```bash
terraform destroy
```

Confirms before deleting:
- Azure AD App registration
- Service Principal
- Client Secret

⚠️ **This does NOT delete the Workato bot or Teams app — remove those manually.**
